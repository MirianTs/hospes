# Hospes

უკონტაქტო ჯავშანი და ჩექინი საქართველოს მცირე სასტუმროებისა და გესთჰაუსებისთვის, ტურისტული რუკით.
Smartstay 2026 ჰაკათონის დემო. სრული სპეციფიკაცია: [SPEC.md](SPEC.md).

| ნაწილი | ტექნოლოგია |
|---|---|
| `backend/` | Node.js + Express + SQLite (better-sqlite3), JWT, `serialport` |
| `web/` | React (Vite), Leaflet + OpenStreetMap, `@vladmandic/face-api` |
| `hardware/hospes_locks/` | Arduino Uno + 4 × SG90 სერვო |
| `hardware/servo-locker/` | ცალკე ლოქერი: Arduino Uno + 4 × SG90, საიტი Web Serial-ით (სერვერის გარეშე) |
| `card-status/` | ცალკე ერთეკრანიანი საიტი: კარი ღიაა თუ დაკეტილი (Node, პორტი 5500, [README](card-status/README.md)) |
| `servo-buttons/` | ცალკე ერთეკრანიანი საიტი: სამი ღილაკი სერვოების გასაღებად (Node, პორტი 5501, [README](servo-buttons/README.md)) |
| `hardware/locker-box-3d/` | ლოქერ-ბოქსის 3D ფაილები (STL, FlashPrint-ის `.gx`, რენდერები, [README](hardware/locker-box-3d/README.md)) |
| `docs/` | პრეზენტაცია (`presentation.pdf`) |

## გაშვება

საჭიროა Node.js 22 ან უფრო ახალი (ტესტირებულია 24-ზე).

```bash
npm run setup
```

```bash
npm run dev
```

- საიტი: http://localhost:5173
- ტელეფონიდან (იმავე Wi-Fi-ზე): `http://<ლეპტოპის-IP>:5173`. მისამართს Vite ტერმინალში წერს, როგორც `Network`.
- API: http://localhost:4000/api/health

პირველ გაშვებაზე ბაზა თავისით ივსება დემო მონაცემებით: 30 გესთჰაუსი მთელ საქართველოში, 113 ადგილი რუკაზე და დემო ანგარიშები. ყველაფრის თავიდან დასაწყებად (ჯავშნები, ატვირთული ფოტოები):

```bash
npm run seed
```

### ერთ მისამართზე (დემოსთვის)

ასე საიტსაც და API-საც ერთი სერვერი ემსახურება, პორტზე 4000:

```bash
npm run build
```

```bash
npm start
```

1. **რეგისტრაცია და ვერიფიკაცია.** „რეგისტრაცია“ → პირადობის ფოტო → სელფი → „შედარება და დადასტურება“. სახეებს ბრაუზერი ადარებს.
2. **ძებნა რუკაზე.** „რუკა“ → თარიღები. ჩანს მხოლოდ ის სასტუმროები, სადაც ოთახი თავისუფალია. კატეგორიების ჩართვით რუკაზე კაფეები, ტურები, გიდები, ბილიკები და ღირსშესანიშნაობები ემატება.

4. **ჩექინი.**

5. **სერვისის მოთხოვნა.** ჯავშანი → „დამატებითი სერვისები“ → მაგალითად, საუზმე.
6. **მფლობელი** (owner@hospes.test) → „დეშბორდი“:
   - ხედავს ჯავშანს და მოთხოვნას, აღნიშნავს „შესრულდა“;
   - „ოთახები და ფასები“ ჩანართში ცვლის ფასს;
   - „გარე ჯავშნები“ ჩანართში ბლოკავს Booking.com-ის ჯავშანს. ამ თარიღებზე ოთახს ვეღარავინ დაჯავშნის.

## Arduino

**შეერთება**
- SG90-ების სიგნალი: D3 (საკეტი 1), D5 (2), D6 (3), D7 (4). ყავისფერი → GND, წითელი → 5V.
- სერვოების კვება: ერთი SG90 Uno-ს 5V-ზეც იმუშავებს. 2–4 სერვოსთვის ცალკე 5V / 2A+ ბლოკი გამოიყენეთ და მისი GND Uno-ს GND-ს შეუერთეთ.
- RC522 ბარათის მკითხველი:

| RC522 | Uno |
|---|---|
| SDA | D10 |
| SCK | D13 |
| MOSI | D11 |
| MISO | D12 |
| IRQ | არაფერი |
| GND | GND |
| RST | D9 |
| 3.3V | 3.3V (არა 5V!) |

მკითხველს დაფა ყოველ 3 წამში ეძებს, ამიტომ მოგვიანებით მიერთებულსაც თავად იპოვის. თუ ვერ პოულობს, შეამოწმეთ სადენები და ისიც, მიდუღებულია თუ არა RC522-ის ფეხები.

**ბარათით შესვლა.** ადმინი → „საკეტი“ (`/lock`):
- მიადეთ ბარათი: კარი იღება, მოვლენა ჟურნალში იწერება და 5 წამში კარი იკეტება.
- ჩანართი „ვის უღებს კარს“ გადართავს ორ რეჟიმს: ნებისმიერი ბარათი ან მხოლოდ დაშვებული.
- ახალ ბარათს ერთი ღილაკით დაამატებთ.
- „ბარათის სიმულაცია“ იმავე ჯაჭვს მკითხველის გარეშე ამოწმებს.

გაღებას სერვერი წყვეტს: დაფა აგზავნის `RFID:<ID>`-ს, სერვერი უკან `OPEN<n>`-ს. სერვერი რომ არ მუშაობს, ბარათი კარს ვერ გააღებს.

**ატვირთვა.** საჭიროა ბიბლიოთეკა **MFRC522** (Library Manager ან `arduino-cli lib install MFRC522`). Backend-ი, სანამ მუშაობს, პორტს იკავებს, ამიტომ ატვირთვამდე გააჩერეთ. Arduino IDE-ში გახსენით `hardware/hospes_locks/hospes_locks.ino` → Board: Arduino Uno → Upload. ან ბრძანებებით (COM3 თქვენი პორტით შეცვალეთ):

```bash
arduino-cli compile --fqbn arduino:avr:uno hardware/hospes_locks
```

```bash
arduino-cli upload -p COM3 --fqbn arduino:avr:uno hardware/hospes_locks
```

**შემოწმება.** Serial Monitor-ში (9600 baud) აკრიფეთ `OPEN1`. კარი გაიღება და 5 წამში დაიკეტება. დაბრუნდება `OPENED1`, მერე `LOCKED1`. კუთხეები სკეტჩის თავშია: `OPEN_ANGLE`, `LOCKED_ANGLE`. სხვა ბრძანებები: `CLOSE1`..`CLOSE4` კარს მაშინვე კეტავს, `PING`-ზე დაფა `PONG`-ს პასუხობს.

**Backend-თან დაკავშირება.**
1. დააკოპირეთ `backend/.env.example` → `backend/.env`.
2. ჩაწერეთ `ARDUINO_PORT=COM3`, ან `ARDUINO_PORT=auto`, რომ დაფა თავად მოიძებნოს.
3. დახურეთ Serial Monitor (პორტს ერთდროულად მხოლოდ ერთი პროგრამა იყენებს).
4. გადატვირთეთ backend.
5. შეამოწმეთ: ადმინი → „Arduino“ ჩანართი → OPEN1..OPEN4.

`ARDUINO_PORT`-ის გარეშე backend დემო რეჟიმში მუშაობს: ბრძანებები მხოლოდ ლოგში იწერება და საიტი ამას აჩვენებს.

## სახის ვერიფიკაცია

- **ახლა დემო რეჟიმია** (`FACE_VERIFICATION=demo` `backend/.env`-ში). ეკრანზე ყველა ნაბიჯი ჩანს, მაგრამ შედარება ყოველთვის წარმატებულია და ფოტოები არსად ინახება. გვერდზე ღილაკიც არის „ფოტოების გარეშე გაგრძელება“.
- ნამდვილი შედარებისთვის ჩაწერეთ `FACE_VERIFICATION=real` და გადატვირთეთ backend.
- მოდელები (`web/public/models`, ~12 MB) `npm install`-ის დროს კოპირდება. ინტერნეტი არ სჭირდება.
- ლეპტოპზე (localhost) კამერა პირდაპირ ბრაუზერში ირთვება. ტელეფონზე `http://IP`-დან ბრაუზერი კამერას არ რთავს, ამიტომ ღილაკი ტელეფონის კამერას ფაილის ასარჩევად ხსნის.
- ზღვარი: `FACE_MATCH_THRESHOLD` (ნაგულისხმევი 0.6, ნაკლები = უფრო მკაცრი).
- ფოტოები ინახება `backend/uploads/`-ში, საჯაროდ არ ჩანს. `npm run seed` მათაც შლის.

## შეზღუდვები (დემო-დონე)

- სახეების შედარების შედეგს სერვერი ბრაუზერისგან იღებს და ენდობა. პილოტისთვის შედარება სერვერზე უნდა გადავიდეს.
- გადახდა სიმულაციაა: ბარათის მონაცემები ბრაუზერიდან არ გადის.
- რუკის ფენებს (Esri-ს სატელიტი, OpenStreetMap) ინტერნეტი სჭირდება. ადგილზე ტელეფონის hotspot-იც საკმარისია.
- seed-ის კაფეები, ტურები, გიდები და გესთჰაუსები გამოგონილია, კოორდინატები მიახლოებითია.
- `backend/.env`-ში `JWT_SECRET` შეცვალეთ, სანამ სერვერს სხვა ქსელში გაუშვებთ.
- პროექტი OneDrive-ის საქაღალდეშია. იქ ფაილების ცვლილებას Vite ზოგჯერ ვერ ამჩნევს, ამიტომ polling რეჟიმი ჩართულია (`web/vite.config.js`).

## API

ყველა მარშრუტი `/api`-ით იწყება. დაცულ მარშრუტებს სჭირდება `Authorization: Bearer <token>`.

- **სერვისი:** `GET /health` (`ok`, დღევანდელი თარიღი, Arduino-ს მდგომარეობა), `GET /config` (`face_verification`, `face_match_threshold`)
- **auth:** `POST /auth/register`, `POST /auth/login`, `GET /auth/me`, `POST /auth/verify` (multipart: `id_doc`, `selfie`, `distance`)
- **public:** `GET /hotels?q=&check_in=&check_out=&min_price=&max_price=&key_type=`, `GET /hotels/:id`, `GET /rooms/:id/availability`, `GET /pois?type=cafe,tour`
- **guest:** `POST /bookings`, `GET /bookings/my`, `GET /bookings/:id`, `POST /bookings/:id/pay`, `POST /bookings/:id/cancel`, `POST /bookings/:id/checkout`, `POST /checkin/code`, `GET|POST /bookings/:id/services`
- **owner:** `GET /owner/hotels`, `GET /owner/bookings`, `PATCH /rooms/:id`, `GET|POST|PATCH|DELETE /owner/services`, `POST /owner/blocks`, `DELETE /owner/blocks/:id`, `GET /owner/service-requests`, `PATCH /owner/service-requests/:id`
- **admin:** `POST /admin/hotels`, `POST /admin/rooms`, `POST /admin/pois`, `GET /admin/users`, `PATCH /admin/users/:id`, `GET /admin/hardware`, `POST /admin/locks/:n/open`
- **card access (admin):** `GET /admin/rfid`, `GET /admin/rfid/stream` (server-sent events), `POST /admin/rfid/cards`, `DELETE /admin/rfid/cards/:uid`, `PATCH /admin/rfid/settings`, `POST /admin/rfid/simulate`
